## Layer Details

### Layer 1: Perception (Gemini Live)

**What it does:**
- Receives audio chunks from user's microphone
- Receives video frames from glasses camera (1 FPS, JPEG)
- Processes in real-time via WebSocket
- Responds with audio (text-to-speech)
- Emits tool calls when action is needed

**Key insight:** Gemini is *stateless* within a session - the system prompt and tools define its capabilities.

### Layer 2: Action (Tool Call Router)

**What it does:**
- Receives tool calls from Gemini
- Decides: handle locally or delegate to Agent?
- Local = instant (<100ms response)
- Remote = async (fire-and-forget)

**The two-tier pattern:**
```
tool_call received
       │
       ▼
┌──────────────────┐
│ Try LOCAL first  │ ← ConstructionConfig.handleToolCall()
└────────┬─────────┘
         │
    ┌────┴────┐
    │         │
 handled   not handled
    │         │
    ▼         ▼
 return    ┌──────────┐
 result    │ AGENT    │ ← Fire to remote Agent
           └──────────┘
```

### Layer 3: Observation (EventStore + Dashboard)

**What it does:**
- Every action emits an event
- Events batch and flush to Supabase
- Dashboard reads and displays timeline
- **Read-only projection** - never blocks user flow

**Event flow:**
```
iOS App                     Server                    Dashboard
   │                          │                          │
   │──event──►EventClient     │                          │
   │          (batches 20)    │                          │
   │              │           │                          │
   │              │──POST────►│ /api/events              │
   │              │           │      │                   │
   │              │           │      ▼                   │
   │              │           │  Supabase                │
   │              │           │      │                   │
   │              │           │      │◄───────query──────│
   │              │           │      │                   │
   │              │           │      │──────data────────►│
```

### Layer 4: Agent (Claude + E2B)

**What it does:**
- Executes complex tasks that need tools
- Runs in isolated E2B sandbox (Firecracker microVM)
- Each session gets its own sandbox
- Has Claude Agent SDK with built-in tools

**Why sandboxed?**
- Security: Customers can't access each other's data
- Isolation: Code execution doesn't affect main system
- Flexibility: Can install packages, write files, run commands

## The Complete Flow

Let's trace "flag this exposed wiring":

```
1. USER: "Flag this exposed wiring"
   │
   └──► [PERCEPTION] Gemini hears + sees
              │
              └──► Emits tool_call: flag_issue(description="exposed wiring")

2. [ACTION] ToolCallRouter receives tool_call
   │
   ├──► LOCAL: SessionManager.flagIssue()
   │         └── Saves flag + photo in memory (instant)
   │         └── Returns: "Issue #1 flagged"
   │
   ├──► EVENT: issue_flagged → EventClient → Supabase
   │
   └──► ASYNC FAN-OUT: Agent task dispatched
              └── "Create ticket for exposed wiring in unit 204"

3. [OBSERVATION] Dashboard updates
   │
   └──► Shows new issue in timeline with photo

4. [AGENT] In background sandbox
   │
   └──► Creates MS Planner ticket
   └──► Sends Slack notification
   └──► (User never waits for this)
```
